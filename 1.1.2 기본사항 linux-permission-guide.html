리눅스 권한 구조
완전 정복

rwx가 왜 4·2·1인지, 755와 644가 웹 서버 표준인 이유, 그리고 find 명령으로 파일·디렉토리를 따로 다루는 법까지 — 한 번에 정리합니다.

🔐 CHAPTER 1

왜 r=4, w=2, x=1 인가?

리눅스 권한은 딱 세 가지 행동을 제어합니다. 이 세 값이 2의 거듭제곱으로 설계된 이유가 있습니다.

r
4
Read · 읽기
+
w
2
Write · 쓰기
+
x
1
Execute · 실행
✦ 4 + 2 + 1 = 7 → rwx (모든 권한)  |  4 + 0 + 0 = 4 → r-- (읽기만)  |  중복 없이 합산 가능
💡
설계 원리

4, 2, 1은 각각 2²=4, 2¹=2, 2⁰=1 즉 이진수 자리값입니다. 서로 다른 거듭제곱을 쓰면 어떤 조합도 유일한 합계를 가집니다. 예를 들어 r+x=5, r+w=6, w+x=3 — 겹치는 숫자가 없어 하나의 숫자만으로 정확히 어떤 권한이 켜졌는지 알 수 있습니다.

💡 실제로는 — 커널 내부에서 rwx는 3비트 플래그로 저장됩니다. 숫자 표기는 그 비트 패턴을 8진수(octal)로 읽는 것입니다.

숫자로 표현 가능한 모든 조합

숫자권한 문자의미대표 쓰임새
7rwx읽기 + 쓰기 + 실행소유자의 디렉토리/실행파일
6rw-읽기 + 쓰기소유자의 일반 파일
5r-x읽기 + 실행그룹/기타의 디렉토리
4r--읽기만그룹/기타의 일반 파일
3-wx쓰기 + 실행거의 사용 안 함
2-w-쓰기만거의 사용 안 함
1--x실행만특수 목적
0---모두 거부완전 잠금
👤 CHAPTER 2

권한은 세 그룹에 적용된다

리눅스는 모든 파일에 대해 소유자 · 그룹 · 기타 세 대상의 권한을 따로 설정합니다.

-
r w x
r - x
r - x
소유자 (Owner) 그룹 (Group) 기타 (Other)
위 예시: rwxr-xr-x = 755
👑

소유자 (Owner)

누구? 파일 만든 사람
755에서 7 = rwx
644에서 6 = rw-
👥

그룹 (Group)

누구? 같은 그룹 사용자
755에서 5 = r-x
644에서 4 = r--
🌍

기타 (Other)

누구? 나머지 모든 사용자
755에서 5 = r-x
644에서 4 = r--
💡
nginx worker는 일반적으로 nginx 또는 nobody 사용자로 실행됩니다. 소유자가 아니므로 기타(Other) 권한이 적용됩니다. 기타에게 읽기(r) 권한이 없으면 permission denied 에러가 발생합니다.
🌐 CHAPTER 3

웹 서버 표준 — 755 디렉토리 / 644 파일

파일과 디렉토리는 같은 숫자여도 의미가 완전히 다릅니다. 이 차이를 이해하면 표준 설정의 이유를 자연스럽게 알게 됩니다.

📁

디렉토리 → 755

r (읽기) 목록 조회
w (쓰기) 파일 생성/삭제
x (실행) 디렉토리 진입 cd
기타 권한 r-x 필수!
📄

파일 → 644

r (읽기) 파일 내용 읽기
w (쓰기) 내용 수정
x (실행) HTML/JS에는 불필요
기타 권한 r-- 이면 충분
⚠️
디렉토리의 x 권한은 파일의 x(실행)와 다릅니다. 디렉토리에서 x는 "그 폴더 안으로 들어갈 수 있는지"를 의미합니다. x가 없으면 cd 명령이 실패하고, 그 안의 파일에도 접근할 수 없습니다.

🛠️ CHAPTER 4

chmod의 함정 — 그리고 올바른 해결책

① 기본 chmod는 해당 항목만 변경

$ chmod 755 dashboard
dashboard/← ✅ 755 적용됨
├─ index.html← ❌ 변경 안 됨
├─ js/← ❌ 변경 안 됨
│  ├─ app.js
│  └─ lib.js
└─ css/← ❌ 변경 안 됨
   └─ style.css

② -R 옵션으로 하위까지 적용하면?

$ chmod -R 755 dashboard  # Recursive(재귀) 적용
dashboard/755 ✅
├─ index.html755 ⚠️ 파일인데 실행 권한!
├─ js/755 ✅
│  ├─ app.js755 ⚠️
└─ css/755 ✅
   └─ style.css755 ⚠️
🚨
문제! -R 755를 쓰면 HTML, JS, CSS 같은 웹 파일에도 실행(x) 권한이 붙습니다. 보안상 불필요한 권한은 최소화해야 합니다. 웹 파일은 읽기(r)만 있으면 충분합니다.

③ 올바른 방법 — find로 디렉토리/파일 분리 적용

📁 디렉토리만 → 755
# -type d : 디렉토리만 선택
find ~/grafana-stack/dashboard \
  -type d \
  -exec chmod 755 {} \;
결과:
dashboard/
dashboard/js/
dashboard/css/
모두 755 ✅
📄 파일만 → 644
# -type f : 파일만 선택
find ~/grafana-stack/dashboard \
  -type f \
  -exec chmod 644 {} \;
결과:
index.html
js/app.js
css/style.css
모두 644 ✅
부분의미
find파일/디렉토리 검색 명령
~/grafana-stack/dashboard검색을 시작할 경로 (하위 전부 포함)
-type d디렉토리(directory)만 선택
-type f일반 파일(file)만 선택
-exec chmod 755 {} \;검색된 각 항목에 chmod 755 실행 ({}에 경로 대입)
✅ CHAPTER 5

실전 웹 서버 권한 설정 — 단계별 가이드

1

현재 권한 확인

설정 전에 현재 상태를 먼저 파악합니다.

$ ls -la ~/grafana-stack/dashboard
2

디렉토리 권한 설정 (755)

모든 하위 디렉토리에 755를 적용합니다.

$ find ~/grafana-stack/dashboard -type d -exec chmod 755 {} \;
3

파일 권한 설정 (644)

모든 하위 파일에 644를 적용합니다.

$ find ~/grafana-stack/dashboard -type f -exec chmod 644 {} \;
4

결과 확인

ls -la로 권한이 올바르게 설정됐는지 확인합니다.

drwxr-xr-x  dashboard/(755)
-rw-r--r--  index.html(644)
drwxr-xr-x  js/(755)
-rw-r--r--  app.js(644)

권한 설정 한눈에 요약

대상권한문자이유
📁 디렉토리 755 rwxr-xr-x Worker가 폴더 안으로 진입하려면 x 필요
📄 웹 파일 (HTML/JS/CSS) 644 rw-r--r-- Worker는 읽기만 필요, 실행 권한 불필요
🔑 실행 스크립트 (.sh) 755 rwxr-xr-x 실행이 필요한 스크립트는 x 권한 필요
🔒 설정/비밀 파일 600 rw------- 소유자만 접근, 비밀번호·키 파일
🎯
핵심 원칙: 권한은 "필요한 최소한만" 부여하는 것이 보안의 기본입니다. 웹 서버 파일은 읽기만, 실행 파일은 실행만, 비밀 파일은 소유자만.
