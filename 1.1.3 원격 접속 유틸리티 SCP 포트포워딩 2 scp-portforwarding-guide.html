📋 CHAPTER 2

cp vs scp — 왜 cp가 있는데 scp가 필요한가?

🏠
이렇게 생각해 보세요!

cp는 내 방 안에서 노트를 복사하는 것이에요. 같은 건물(컴퓨터) 안에서만 가능하죠.

scp는 친구 집으로 노트를 잠금 봉투에 넣어 택배로 보내는 것이에요. 다른 건물(원격 컴퓨터)로 보내야 하고, 중간에 누가 열어봐도 내용을 알 수 없어요!

💡 실제로는 — scp는 내부적으로 SSH 프로토콜을 사용합니다. 그래서 파일 복사 + 암호화 + 로그인 인증이 한 번에 처리됩니다.

cp — 같은 PC 안에서 복사

📄
a.txt
/home/zeta/
→
📋
cp 명령
네트워크 없음
→
📄
b.txt
/home/zeta/backup/
# 같은 PC 안에서 파일 복사
$ cp a.txt b.txt
# 다른 폴더로 복사
$ cp a.txt /home/zeta/Downloads/
# 폴더 전체 복사 (-r 옵션)
$ cp -r my_folder/ /home/zeta/backup/

scp — 다른 PC로 암호화 전송

💻
내 PC
test.py
→
🔒
SSH 암호화
Port 22
→
🖥️
원격 서버
192.168.0.50
→
📄
저장 완료
/home/zeta/test.py
# 기본 구조: scp [보낼파일] [사용자]@[IP]:[받을경로]
$ scp test.py zeta@192.168.0.50:/home/zeta/
💡
scp 구조 분석
scp = 안전 복사 명령어  |  test.py = 보낼 파일  |  zeta = 원격 사용자명  |  192.168.0.50 = 원격 IP  |  /home/zeta/ = 저장 위치
📦 CHAPTER 3

scp 방향 — 헷갈리지 않는 법

🎯
이것만 기억!    scp  출발지   도착지
왼쪽이 나가는 곳, 오른쪽이 도착하는 곳입니다. 항상 같아요!
⬆️ 내 PC → 원격 서버 (업로드)
# 파일 전송
test.py  →  zeta@192.168.0.50:/home/zeta/
 
$ scp test.py zeta@192.168.0.50:/home/zeta/
 
# 폴더 전송 (-r 옵션)
$ scp -r my_project/ zeta@192.168.0.50:~
 
# Downloads 폴더 지정
$ scp robot_config.yaml zeta@192.168.0.50:~/Downloads/
⬇️ 원격 서버 → 내 PC (다운로드)
# 파일 가져오기 (마지막 . = 현재 폴더)
zeta@192.168.0.50:~/result.txt → ./
 
$ scp zeta@192.168.0.50:~/result.txt ./
 
# 로그 파일 가져오기
$ scp zeta@192.168.0.50:~/syslog ./syslog_backup.txt
 
# 폴더 전체 가져오기
$ scp -r zeta@192.168.0.50:~/lerobot_logs ./
⚠️
권한 오류가 날 때 — /var/log/syslog 같은 시스템 파일은 권한 때문에 바로 scp가 안 됩니다. 서버에서 먼저 홈 디렉토리로 복사하세요.
# 서버에서: 홈 디렉토리로 복사
서버$ sudo cp /var/log/syslog ~/syslog
# 내 PC에서: scp로 가져오기
내PC$ scp zeta@192.168.0.50:~/syslog ./
🏠 CHAPTER 4

~ (틸드) 는 무엇인가요?

🏠
집 주소 단축키!

리눅스에서 ~ (틸드)는 "내 홈 디렉토리"를 뜻하는 단축기호예요. 사용자 이름에 따라 가리키는 폴더가 달라집니다. 학교 이름이 달라도 "우리 학교"라고 말하면 각자 자기 학교를 뜻하는 것처럼요!

💡 결론 — scp test.py zeta@192.168.0.50:~ 와 scp test.py zeta@192.168.0.50:/home/zeta/ 는 완전히 같은 의미입니다. 교육 자료에서는 이해하기 쉽도록 풀어쓴 경로를 더 많이 사용해요.

사용자: zeta
~
=
/home/zeta
사용자: pi
~
=
/home/pi
사용자: nvidia (Jetson)
~
=
/home/nvidia
사용자: ubuntu
~
=
/home/ubuntu
# 아래 두 명령은 완전히 같습니다
$ scp test.py zeta@192.168.0.50:~
$ scp test.py zeta@192.168.0.50:/home/zeta/
 
# 하위 폴더도 가능
$ scp test.py zeta@192.168.0.50:~/Downloads/
# = /home/zeta/Downloads/
⚙️ CHAPTER 5

scp 주요 옵션 모음

옵션의미예시
-r 폴더 전체 (recursive) scp -r my_project/ zeta@IP:~/
-P 포트 SSH 포트 지정 (대문자 P!) scp -P 2222 test.py zeta@IP:~/
-i 키파일 SSH 개인키 지정 scp -i ~/.ssh/id_ed25519 test.py zeta@IP:~/
-v 진행 상황 상세 출력 (verbose) scp -v big_file.zip zeta@IP:~/
🚨
포트 옵션 대소문자 주의!
ssh -p 2222 → 소문자 p     scp -P 2222 → 대문자 P
두 명령어가 다릅니다. 실수가 많은 부분이에요!
포트 옵션 예제
# SSH 접속 - 소문자 p
$ ssh -p 2222 zeta@192.168.0.50
 
# SCP 전송 - 대문자 P
$ scp -P 2222 test.py zeta@192.168.0.50:~/
🪟 CHAPTER 6

Windows ↔ Ubuntu 파일 전송

⚠️
경로 형식이 다릅니다!

Windows와 Linux는 경로 구분자가 달라요. Windows는 \(백슬래시), Linux는 /(슬래시)를 씁니다. SCP에서 헷갈리기 쉬운 부분이에요.

🪟 Windows 경로
C:\Users\user\Desktop\test.py
# 백슬래시(\) 사용
🐧 Linux 경로
/home/zeta/test.py
# 슬래시(/) 사용

Windows → Ubuntu (업로드)

Windows PowerShell
# Windows 파일을 Ubuntu로 전송
PS C:\Users\user\Desktop> scp C:\Users\user\Desktop\test.py zeta@192.168.0.50:~/

Ubuntu → Windows (다운로드)

⭐
가장 쉬운 방법 — Ubuntu에서 Windows로 보낼 때는 Windows PowerShell에서 당겨오는 것이 훨씬 편합니다. Windows OpenSSH 버전마다 경로 형식이 달라 Ubuntu에서 보내면 헷갈려요.
Windows PowerShell (바탕화면에서 실행)
# Ubuntu 파일을 Windows 현재 폴더로 가져오기
PS C:\Users\user\Desktop> scp zeta@192.168.0.50:~/result.csv .
# . = PowerShell 현재 위치 (바탕화면으로 저장됨)
방향권장 방식이유
Windows → UbuntuPowerShell에서 scp 실행경로 형식 일관성
Ubuntu → WindowsPowerShell에서 당겨오기Windows SSH 버전 호환성
Ubuntu에서 Windows로 push잘 안 씀Windows OpenSSH 경로가 버전마다 다름
🔌 CHAPTER 7

SSH 포트포워딩 — 원격 서비스를 내 PC처럼

🚇
지하철 터널 비유!

원격 서버 안에 Grafana가 실행 중인데, 서버가 인터넷에 공개되어 있지 않아 브라우저로 바로 접속이 안 돼요.

SSH 포트포워딩은 원격 서버까지 지하 터널(SSH)을 뚫고, 그 터널 끝에 있는 Grafana 입구를 내 PC 입구처럼 사용하는 것이에요. 외부에서 볼 때는 내 PC 로컬에서 실행되는 것처럼 보여요!

💡 실제로는 — ssh -L 내포트:서버에서볼주소:서버포트 사용자@서버IP
이 명령 하나로 암호화된 SSH 터널이 생기고, 내 PC 포트로 접속하면 자동으로 서버 포트로 전달됩니다.

포트포워딩 흐름도 (Grafana 예시)

🌐 브라우저
http://localhost:3000
↓
💻 내 PC
3000번 포트
↓
🔒 SSH 암호화 터널 (Port 22)
↓
🖥️ 원격 서버
localhost:3000
↓
📊 Grafana
3000번 포트로 실행 중

ssh -L 명령어 구조 분석

# 구조: ssh -L [내PC포트]:[서버기준주소]:[서버포트] [사용자]@[서버IP]
$ ssh -L 3000:localhost:3000 zeta@192.168.0.50
 
# 해석:
# -L 3000 → 내 PC의 3000번 포트로 들어오면
# :localhost → SSH로 접속한 서버 기준으로 localhost(자기 자신)의
# :3000 → 3000번 포트로 전달해라
# zeta@192.168.0.50 → 이 서버에 SSH로 연결
💡
명령 실행 후 터미널이 열려 있는 동안 터널이 유지됩니다. 브라우저에서 http://localhost:3000으로 접속하면 원격 Grafana가 열려요. 터미널을 닫으면 터널도 닫힙니다.

🌐 CHAPTER 9

SSH 포트포워딩 vs 웹 포워딩 — 무엇이 다른가?

🎯
핵심 차이

SSH 포트포워딩은 개발자가 원격 서버 내부 서비스에 몰래 안전하게 접속하는 개인용 터널이에요.

웹 포워딩(Nginx 등)은 일반 사용자들이 도메인 주소로 서비스에 접속할 수 있도록 공개적으로 길을 만들어주는 것이에요.

구분SSH 포트포워딩웹 포워딩 (Nginx)
주 사용자개발자, 관리자일반 사용자
도구SSH 클라이언트Nginx, Apache, DNS
보안SSH 암호화 터널HTTPS 또는 내부 프록시
접속 방식localhost:포트https://mycompany.com
목적원격 내부 서비스 임시 접속외부 서비스 정식 공개
공개 여부비공개 (개인만)공개 (누구든 접속)
대표 예시Jupyter, Grafana, ROSBridge홈페이지, API 서버, 관리 페이지
