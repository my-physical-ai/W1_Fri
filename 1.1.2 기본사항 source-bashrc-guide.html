1 Shell(셸) — 컴퓨터와 대화하는 창구

🍳
초등학생도 이해하기!

레스토랑에 가면 주방(Kitchen)에 직접 들어가지 않죠? 웨이터에게 "파스타 주세요"라고 말하면, 웨이터가 주방에 전달하고, 요리가 나옵니다.

컴퓨터도 마찬가지예요! CPU(주방)에 직접 말할 수 없으니, Shell(웨이터)에게 명령을 전달하면 Shell이 CPU에게 대신 전해주고, 결과를 가져다줍니다.

💡 실제로는 — Shell은 사용자의 텍스트 명령을 받아서 운영체제(OS) 커널에 전달하는 명령어 해석기(Command Interpreter)입니다. Bash, Zsh, Fish 등 다양한 종류가 있습니다.

🕰️ Shell은 왜 만들어졌을까?

1960년대 컴퓨터는 방 하나를 꽉 채울 만큼 컸다

초창기 컴퓨터는 구멍 뚫린 카드(펀치 카드)로 명령을 내렸어요. 프로그램을 바꾸려면 카드를 새로 뚫어야 했죠. 너무 불편하지 않나요? 😱

그래서 사람들은 생각했어요: "키보드로 글자를 쳐서 명령하면 안 될까?"

1971년 최초의 Unix Shell 탄생! — Thompson Shell

켄 톰슨(Ken Thompson)이 최초의 Shell을 만들었어요. 드디어 키보드로 ls(파일 목록), cd(폴더 이동) 같은 명령을 칠 수 있게 되었습니다!

1989년 Bash 탄생! — 지금 우리가 쓰는 Shell

브라이언 폭스(Brian Fox)가 Bash (Bourne-Again SHell)를 만들었어요. "다시 태어난 Shell"이라는 뜻인데, 이전 Shell의 장점을 모두 합쳐서 만든 거예요. 지금 라즈베리파이에서 쓰는 것도 바로 이 Bash입니다!

2 .bashrc — 터미널의 "자동 설정 메모장"

📋
초등학생도 이해하기!

학교에 갈 때마다 "교복 입기 → 가방 챙기기 → 물통 넣기"를 반복하죠? 매일 똑같은 일이니, 체크리스트를 벽에 붙여두면 까먹지 않아요.

.bashrc는 터미널의 체크리스트예요! 터미널이 열릴 때마다 자동으로 이 리스트를 읽고, 적혀 있는 설정을 하나하나 실행합니다.

💡 실제로는 — ~/.bashrc는 Bash 셸이 비-로그인 대화형(interactive non-login) 모드로 시작할 때 자동으로 실행되는 스크립트 파일입니다. 환경 변수, alias, 함수 정의 등이 들어갑니다.

📛
이름의 의미
.bash = Bash 셸 전용
rc = Run Commands (실행할 명령들)
점(.) = 숨김 파일 (ls로 안 보임)
📍
파일 위치
~/.bashrc
~ = 홈 디렉토리
예: /home/zeta/.bashrc
⏰
언제 실행되나?
새 터미널 창을 열 때
SSH로 접속할 때
source ~/.bashrc 할 때

📦 .bashrc 안에는 뭐가 들어있을까?

🎒
학교 가방에 비유하면!

가방(bashrc) 안에 여러 물건이 있어요:
🏷️ 이름표(alias) — "긴 이름을 짧은 별명으로"
🔑 열쇠(환경 변수) — "이 프로그램은 여기에 있어"
📖 교과서(source 명령) — "ROS2 환경 불러와!"
🐍 사육장(conda init) — "Python 환경 준비해!"

~/.bashrc 예시 (라즈베리파이 LeKiwi) 
# ────────────────────────────────────────────
# 🏷️ alias (별명) — 긴 명령을 짧게!
# ────────────────────────────────────────────
alias ll='ls -la'        # ll만 치면 상세 목록
alias gs='git status'    # gs만 치면 git 상태

# ────────────────────────────────────────────
# 🔑 환경 변수 — 프로그램 찾는 길 안내
# ────────────────────────────────────────────
export PATH="$HOME/.local/bin:$PATH"

# ────────────────────────────────────────────
# 🐍 conda init 블록 — Conda 환경 준비
# ────────────────────────────────────────────
# >>> conda initialize >>>
# (conda가 자동으로 추가한 블록)
# <<< conda initialize <<<

# ────────────────────────────────────────────
# 📖 ROS2 환경 자동 로드
# ────────────────────────────────────────────
source /opt/ros/jazzy/setup.bash

🤔 왜 이런 파일이 필요하게 되었을까?

😫
문제: 매번 똑같은 설정을 반복해야 했다
초기 컴퓨터에서는 터미널을 열 때마다 "이 프로그램은 여기 있어", "이 별명을 써줘" 같은 설정을 매번 손으로 입력해야 했어요. 10개만 설정해도 매일 10번씩 같은 걸 쳐야 하니 너무 비효율적이었죠.
💡
아이디어: "파일에 적어두고 자동으로 읽으면 되잖아!"
개발자들이 생각했어요: 설정 명령들을 하나의 파일에 적어두고, Shell이 시작할 때마다 자동으로 읽게 하면 되겠다! 그래서 "Run Commands"의 약자 rc가 파일 이름에 붙게 되었습니다.
✅
해결: .bashrc 탄생!
.bashrc 파일에 원하는 설정을 적어두면, 터미널이 열릴 때마다 자동으로 실행됩니다. 한 번 적으면 영원히 적용되니 정말 편리하죠!

3 source — "지금 당장 읽어!" 명령어

📢
초등학생도 이해하기!

체크리스트를 벽에 새로 붙였다고 해봐요. 하지만 다음 날 아침에야 그걸 보겠죠? 지금 당장 그 리스트대로 하고 싶으면 어떡할까요?

"엄마! 새 체크리스트 붙였으니까 지금 바로 한번 읽어봐!" 하고 말하는 거예요. source가 바로 그 역할입니다!

💡 실제로는 — source는 지정한 파일의 명령들을 현재 실행 중인 셸에서 바로 실행합니다. 새 터미널을 열지 않아도 변경된 설정이 즉시 적용됩니다.

source가 하는 일 — 단계별로 보기

✏️
.bashrc 수정
새 설정 추가
📣
source 실행
"지금 바로 읽어!"
✅
즉시 적용!
재시작 필요 없음
❌ source 없이 — 반영 안 됨
# .bashrc에 alias 추가 후
zeta@lekiwi:~$ ll
bash: ll: command not found
# 😤 아직 적용 안 됨!
# 터미널을 닫았다 열어야 함
✅ source 사용 — 즉시 적용
# .bashrc에 alias 추가 후
zeta@lekiwi:~$ source ~/.bashrc
zeta@lekiwi:~$ ll
total 48
drwxr-xr-x ...
# 🎉 바로 동작!

⚡ source의 비밀: "현재 셸에서" 실행한다

🎨
여기가 가장 중요해요!

source와 bash 명령은 비슷해 보이지만 완전히 달라요!

🎨 source = "내 방에서 색칠하기" — 색칠한 결과가 내 방에 남아요.
🏫 bash로 실행 = "다른 교실에서 색칠하기" — 끝나면 그 교실은 사라지고, 내 방은 그대로예요.

💡 실제로는 — source는 현재 프로세스에서 스크립트를 실행하므로 환경 변수 변경이 현재 셸에 유지됩니다. bash script.sh는 자식 프로세스(서브셸)를 생성하여 실행하므로, 환경 변수 변경이 부모 셸에 반영되지 않습니다.

source vs bash 차이 실험 
# test.sh 파일을 만들어보자
echo 'export MY_NAME="빅맨"' > test.sh

# ❌ bash로 실행 — 서브셸에서 실행 → 부모에 영향 없음
bash test.sh
echo $MY_NAME
                    # 아무것도 안 나옴! 😱

# ✅ source로 실행 — 현재 셸에서 실행 → 바로 적용!
source test.sh
echo $MY_NAME
빅맨                  # 바로 나옴! 🎉
source는 현재 셸(내 방)에서 직접 실행하므로 설정이 유지되고, bash는 새 서브셸(다른 교실)을 만들어 실행하므로 끝나면 설정이 사라집니다.
💡
축약형: source 대신 점(.)을 사용할 수 있어요!
. ~/.bashrc는 source ~/.bashrc와 완전히 같은 뜻입니다.

4 source ~/.bashrc vs 가상환경 — 핵심 차이!

🏘️
가장 중요한 비유!

source ~/.bashrc = "내 방 꾸미기"
벽에 포스터 붙이고, 책상 위치 바꾸고... 바뀐 건 모든 활동에 영향을 줘요. 방에서 공부하든 게임하든 바뀐 환경 그대로 적용됩니다.

가상환경 = "특별한 작업실 만들기"
미술 작업실에는 물감과 캔버스만, 과학 실험실에는 비커와 시약만 있어요. 각 방마다 다른 도구가 있고, 다른 방에는 영향을 주지 않습니다. 들어가고(activate) 나올 수 있어요(deactivate).

📄

source ~/.bashrc

비유

영향 범위
🌍 모든 작업에 영향
끄기/켜기
❌ 불가능 (항상 적용)
격리
❌ 격리 없음
대상
환경 변수, alias, PATH
예시

🎯 가장 중요한 차이 3가지

1️⃣
격리 vs 공유
가상환경은 각 프로젝트의 패키지를 격리합니다. A 프로젝트에서 numpy 1.x를 쓰고, B에서 2.x를 쓸 수 있어요.

.bashrc는 모든 터미널에 공통 적용됩니다. 격리 기능이 없어요.
2️⃣
들어갔다 나올 수 있나?
가상환경은 activate로 들어가고 deactivate로 나올 수 있어요.

.bashrc 설정은 터미널이 켜진 동안 항상 적용됩니다. 끄기/켜기가 없어요.
3️⃣
목적이 다르다!
.bashrc는 셸 환경 전체를 설정합니다 (ROS2 경로, alias, 변수 등).

가상환경은 Python 패키지만 관리합니다. 서로 다른 레벨의 도구예요!

🏗️ 전체 구조에서 보면?

🏠 ~/.bashrc — 셸 전체 환경 (내 방 꾸미기)
alias 별명
PATH 경로
source ROS2
conda init
⬇️ 위에서 설정한 환경 안에서
🔬 가상환경 — Python 격리 공간 (작업실)
conda activate lerobot
python 3.10

⬇️ 가상환경 안에서

💡
핵심 정리: .bashrc는 건물 전체의 기본 설정(전기, 수도, 인터넷)이고, 가상환경은 그 건물 안에서 각 방의 가구와 도구를 따로 관리하는 것입니다. 두 개는 경쟁하는 게 아니라 함께 쓰는 것이에요!

🔄 실제 작업 흐름 예시

LeKiwi 로봇 작업 시 실제 흐름 
# ① SSH로 라즈베리파이 접속
ssh zeta@lekiwi

# ② .bashrc가 자동 실행됨 → ROS2 환경 로드 완료!
#    (source /opt/ros/jazzy/setup.bash 가 자동 실행된 것)
zeta@lekiwi:~$

# ③ ROS2 명령 바로 사용 가능 (.bashrc 덕분!)
ros2 topic list
/rosout

# ④ Python 작업이 필요하면 가상환경 활성화
conda activate lerobot
(lerobot) zeta@lekiwi:~$

# ⑤ 이 안에서 Python 작업 (패키지가 격리되어 있음)
python train.py

# ⑥ 작업 끝나면 가상환경 나오기
conda deactivate
zeta@lekiwi:~$       # ROS2는 여전히 사용 가능!

5 source는 .bashrc에만 쓰이는 게 아니에요!

source는 "파일을 현재 셸에서 실행하라"는 범용 명령이에요. 다양한 곳에서 활용됩니다:

🤖
ROS2 환경
source /opt/ros/jazzy/setup.bash
ROS2 명령어와 환경 변수 로드
🐍
Python venv
source venv/bin/activate
Python 가상환경 활성화
⚙️
.bashrc 재로드
source ~/.bashrc
변경된 셸 설정 즉시 적용
🔐
환경 변수 파일
source .env
API 키 등 비밀 변수 로드
⚠️
재미있는 사실: Python venv의 source venv/bin/activate도 결국 source 명령을 사용합니다! activate 스크립트가 현재 셸의 PATH를 바꿔서 해당 가상환경의 Python을 먼저 찾도록 하는 것이에요. 결국 source 없이는 가상환경도 작동하지 않습니다!

rc는 "Run Commands"의 약자입니다. 1965년 MIT의 CTSS(Compatible Time-Sharing System)에서 유래했어요.

당시 시스템에는 runcom이라는 기능이 있었는데, "이 파일에 적힌 명령들을 실행해라(run commands)"라는 뜻이었습니다. 이 전통이 Unix → Linux → 오늘날까지 이어져서, .bashrc, .vimrc, .condarc 등 설정 파일 이름에 "rc"가 붙게 되었습니다.

리눅스에서 볼 수 있는 rc 파일들:

.bashrc .vimrc .condarc .nanorc .npmrc .gitconfig

Bash 셸은 어떻게 시작되느냐에 따라 읽는 파일이 달라요:

파일 언제 읽히나? 비유
~/.profile 로그인할 때 딱 1번 🏠 집에 들어올 때 (신발 벗기, 불 켜기)
~/.bashrc 터미널 열 때마다 📋 방에 들어갈 때마다 (체크리스트 확인)
~/.xsessionrc GUI 로그인할 때 🖥️ 모니터 앞에 앉을 때 (한글 입력기 등)
~/.condarc conda 명령 사용할 때 🐻 Conda 전용 설정 (채널, auto_activate 등)

실용적인 원칙: 거의 모든 설정은 ~/.bashrc에 넣으면 됩니다. SSH로 접속해도, 터미널을 새로 열어도 항상 읽히니까요!

📋 오늘 배운 것 완전 정리

  • Shell(셸)은 사람과 컴퓨터 사이의 웨이터다 — 명령을 전달하고 결과를 가져온다
  • .bashrc는 터미널의 자동 체크리스트다 — 열릴 때마다 자동 실행된다
  • rc는 "Run Commands"의 약자 — 1965년 MIT에서 시작된 전통이다
  • source는 "지금 당장 읽어!" 명령이다 — 현재 셸에서 직접 실행하므로 설정이 유지된다
  • source는 현재 셸(내 방)에서 실행하고, bash는 서브셸(다른 교실)에서 실행한다
  • .bashrc는 건물 전체 설정, 가상환경은 각 방의 도구 관리 — 함께 쓰는 것이다
  • 가상환경은 들어갔다 나올 수 있지만(activate/deactivate), .bashrc 설정은 항상 적용된다
