CUDA 런타임 라이브러리
libcudart.so.12 완전 정복

PyTorch 한 줄 .cuda() 뒤에서 GPU와 실제로 대화하는 "통역사"의 정체. 왜 이 파일이 필요하고, 왜 오류가 나며, 최근엔 왜 설치가 쉬워졌는지 끝까지 풀어봅니다.

★한눈에 보는 전체 구조

image = torch.randn(1, 3, 224, 224).cuda()

1왜 "런타임 라이브러리"가 필요할까?

요리사가 직접 전기 배선과 가스 압력까지 알 필요는 없습니다. 중간에서 정리해주는 사람이 있기 때문이죠. PyTorch와 GPU 사이에도 그런 "주방 매니저"가 있습니다.

👨‍🍳
이해하기 쉽게 — 주방 비유

요리사(PyTorch)는 "재료를 냉장고에 넣어줘", "불 켜줘", "오븐 돌려줘"라고 요청만 합니다. 전기 배선이나 가스 압력은 몰라도 됩니다. 그 요청을 받아 실제 주방 절차로 옮겨주는 사람이 바로 주방 매니저 = CUDA Runtime Library입니다.

💡 실제로는 — PyTorch는 "GPU에 올려줘"라고만 요청하고, libcudart.so가 디바이스 관리·스트림 관리·에러 처리·실행 제어 같은 실제 절차를 수행합니다.

3왜 오류가 날까?

아래 오류는 입문자가 가장 자주 만나는 메시지입니다. 뜻은 의외로 단순합니다.

ImportError: libcudart.so.12: cannot open shared object file
🔍
오류의 뜻

PyTorch가 CUDA 12 런타임 라이브러리를 찾고 있는데, 리눅스가 그 파일을 못 찾았다는 뜻입니다.

원인은 보통 셋 중 하나

1

파일이 아예 없음

CUDA 런타임이 설치되지 않은 상태.

2

파일은 있는데 경로를 모름

LD_LIBRARY_PATH 등 검색 경로에 등록되어 있지 않음.

3

버전 불일치

PyTorch는 CUDA 12용인데 시스템엔 CUDA 11용만 있는 경우 — 서로 안 맞음.

⚠️
흔한 증상 3종 세트: libcudart.so not found · CUDA version mismatch · torch.cuda.is_available() == False

4왜 실행파일 안에 전부 넣지 않을까?

물론 다 넣을 수도 있습니다. 하지만 그러면 모든 프로그램이 같은 CUDA 라이브러리를 각자 짊어지게 됩니다. 그래서 "따로 분리해서 공유"하는 구조를 택합니다.

📦 전부 포함하면

  • 프로그램마다 CUDA 라이브러리 중복 보유
  • 용량이 커짐
  • 업데이트가 어려움
  • 보안 패치가 어려움
  • GPU 드라이버와 충돌 가능
➡️

🔗 런타임으로 분리하면

  • 여러 프로그램이 공통 라이브러리 공유
  • 용량 절약
  • 업데이트 쉬움
  • 보안 패치 쉬움
  • GPU 상황에 맞게 실행 중 처리
🧩
GPU처럼 하드웨어와 직접 연결되는 기능은 미리 통째로 박아넣기보다 실행 중에 불러오는 구조가 자연스럽습니다. 그래서 "런타임" 라이브러리입니다.

5PyTorch는 어떻게 "쉬워졌나"?

예전엔 사용자가 모든 버전을 손으로 맞춰야 했습니다. 최근엔 PyTorch가 CUDA 런타임을 패키지 안에 함께 담아 배포하는 흐름으로 바뀌었습니다.

🕰️ 과거 방식

  • NVIDIA Driver 설치
  • CUDA Toolkit 설치
  • cuDNN 설치
  • PyTorch CUDA 버전 맞추기
  • 환경변수 / LD_LIBRARY_PATH 설정
➡️

🚀 최근 방식

  • PyTorch wheel이 CUDA 런타임 포함
  • pip install torch 후 바로 사용
  • 설치 실패 감소
  • Docker/클라우드 재현성 향상
  • 초보자 진입장벽 감소

PyTorch 공식 설치 페이지는 CUDA 버전별 설치 명령을 따로 제공합니다. 예를 들어 CUDA 12.1용 wheel은 cu121 인덱스를 사용합니다.

# CUDA 12.1용 PyTorch 설치 예시
pip install torch --index-url https://download.pytorch.org/whl/cu121
📈
최신 흐름: 2026년 PyTorch 릴리스에서는 PyPI wheel이 CUDA 13.0을 기본 포함하는 방향까지 진행되고 있습니다.

일반적인 PyTorch 사용자라면, 아래 세 줄 정리로 충분합니다.

즉 pip install torch (또는 공식 명령)으로 설치하면, 필요한 CUDA 런타임 라이브러리가 PyTorch 안에 함께 들어옵니다.

⚙️CUDA C++를 직접 컴파일할 때

⚙️Jetson 등 특수 임베디드 환경

7그런데 드라이버는 왜 끝까지 따로일까?

PyTorch가 CUDA 런타임을 챙겨와도, NVIDIA Driver만큼은 절대 패키지 안에 못 넣습니다. 운영체제 커널과 GPU 하드웨어에 직접 붙어야 하기 때문입니다.

📦

PyTorch에 포함 가능

✅CUDA Runtime
✅cuBLAS
✅cuDNN 일부
✅NCCL 등
🚫

포함 불가

❌NVIDIA GPU Driver
🔌OS 커널 + GPU 하드웨어에 직접 결합
📥그래서 pip가 아닌 별도 설치 필요
🧱
기억할 것: 드라이버는 OS와 GPU 사이의 "진짜 하드웨어 제어자"입니다. PyTorch가 아무리 똑똑해도 이 계층은 직접 대체할 수 없습니다.
