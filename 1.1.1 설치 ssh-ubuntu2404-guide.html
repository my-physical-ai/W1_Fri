SSH가 무엇인가요?

💡
한 줄 요약 — SSH(Secure Shell)는 멀리 있는 컴퓨터를 안전하게 원격으로 조종하는 통신 방법이에요.
📞
이렇게 생각해 보세요!

옛날에는 선생님 방에 들어가서 직접 말해야 했어요. 그런데 전화가 생기면서 멀리서도 선생님과 대화할 수 있게 됐죠.

SSH는 이 전화와 비슷한데, 일반 전화가 아니라 도청 불가능한 암호 전화예요. 내가 타이핑하는 명령어가 암호화되어 전달되고, 서버의 답장도 암호화되어 돌아와요. 중간에 누가 훔쳐봐도 알아볼 수 없어요!

💡 실제로는 — SSH는 공개키 암호화(Public Key Cryptography)와 대칭키 암호화를 함께 사용해서 통신 채널을 암호화합니다. 포트 기본값은 22번이에요.

🔑 CHAPTER 2

SSH 연결 원리 — 어떻게 안전한가요?

🏦
은행 금고 비유

은행 금고에는 두 개의 열쇠가 있어요. 하나는 은행(서버)이 보관하는 자물쇠(공개키)고, 다른 하나는 내가 갖고 있는 열쇠(개인키)예요.

은행에 자물쇠를 미리 맡겨두면, 내 열쇠로만 금고를 열 수 있어요. 열쇠 없는 사람은 아무리 시도해도 열 수 없죠!

💡 실제로는 — SSH 키 페어(Key Pair)는 공개키(public key)와 개인키(private key)로 구성돼요. 공개키는 서버에 등록하고, 개인키는 절대 외부에 유출하면 안 됩니다.

공개키 / 개인키 구조

🔑 개인키 (Private Key) — 내 PC 보관
-----BEGIN OPENSSH PRIVATE KEY-----
b3BlbnNzaC1rZXktdjEAAAAA...
AAA...절대 외부 유출 금지!...
-----END OPENSSH PRIVATE KEY-----
📍 ~/.ssh/id_ed25519
🔓 공개키 (Public Key) — 서버에 등록
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5...
AAAAB3NzaC1yc2EAAA... zeta@zeta-MS-7E12
📍 서버의 ~/.ssh/authorized_keys

Ubuntu 24.04 SSH 단계별 설치

💡
Ubuntu 24.04는 OpenSSH가 기본 포함되어 있어서 설치는 간단합니다. 아래 단계를 순서대로 따라하세요.
1

패키지 목록 업데이트

최신 패키지 정보를 가져옵니다

설치 전에 항상 패키지 목록을 먼저 업데이트해야 최신 버전을 받을 수 있어요.

zeta@zeta-MS-7E12:~$ sudo apt update
📤 예상 출력
Hit:1 http://archive.ubuntu.com/ubuntu noble InRelease
Get:2 http://archive.ubuntu.com/ubuntu noble-updates InRelease
...

OpenSSH 서버 설치

SSH 서버 데몬을 설치합니다

OpenSSH Server는 내 컴퓨터를 원격 접속 가능하게 만드는 프로그램이에요. 이것을 설치해야 다른 PC에서 SSH로 접속해 올 수 있어요.

# OpenSSH 서버 설치 (-y 는 설치 확인을 자동으로 Yes 처리)
zeta@zeta-MS-7E12:~$ sudo apt install openssh-server -y
📤 예상 출력
Reading package lists... Done
Building dependency tree... Done
The following packages will be installed:
  openssh-server openssh-sftp-server
Setting up openssh-server... Done
💡
Ubuntu 24.04는 이미 설치된 경우가 많아요. 그럴 때는 already the newest version 메시지가 나오면 정상이에요!
3

SSH 서비스 상태 확인

서버가 제대로 실행 중인지 확인합니다

설치 후 SSH 서비스가 정상적으로 실행 중인지 확인해 보세요.

# SSH 서비스 상태 확인
zeta@zeta-MS-7E12:~$ sudo systemctl status ssh
📤 정상 출력 (active 확인!)
● ssh.service - OpenBSD Secure Shell server
  Loaded: loaded (/lib/systemd/system/ssh.service)
  Active: active (running) since Mon 2025-01-01 10:00:00
  Process: ... sshd -D
⚠️
inactive (dead) 가 보이면 아직 실행이 안 된 것이에요. 다음 명령어로 시작하세요: sudo systemctl start ssh
4

자동 시작 설정 & 서비스 시작

부팅 시 자동으로 SSH가 실행되도록 설정합니다

# 부팅 시 자동 시작 등록 (한 번만 설정하면 됨)
zeta@zeta-MS-7E12:~$ sudo systemctl enable ssh
# SSH 서비스 지금 바로 시작
zeta@zeta-MS-7E12:~$ sudo systemctl start ssh
📤 enable 예상 출력
Synchronizing state of ssh.service...
Created symlink /etc/systemd/system/sshd.service → /lib/systemd/system/ssh.service
5

방화벽 설정 (UFW)

SSH 포트 22번을 허용합니다

UFW는 Ubuntu의 기본 방화벽이에요. 방화벽이 활성화되어 있다면 SSH 포트를 열어줘야 해요.

# 현재 방화벽 상태 확인
zeta@zeta-MS-7E12:~$ sudo ufw status
 
# SSH(22번 포트) 허용
zeta@zeta-MS-7E12:~$ sudo ufw allow ssh
 
# UFW 방화벽 활성화 (비활성화 상태라면)
zeta@zeta-MS-7E12:~$ sudo ufw enable
 
# 최종 상태 확인
zeta@zeta-MS-7E12:~$ sudo ufw status verbose
📤 ufw status 정상 출력
Status: active
 
To          Action    From
--          ------    ----
22/tcp      ALLOW IN  Anywhere
22/tcp (v6)  ALLOW IN  Anywhere (v6)
💡
방화벽이 inactive면 UFW가 꺼진 상태예요. 이 경우 별도로 허용하지 않아도 SSH 접속이 됩니다. 하지만 보안을 위해 UFW를 활성화하고 SSH만 열어두는 것을 권장해요.
6

내 IP 주소 확인

다른 PC에서 접속할 때 필요한 주소를 확인합니다

# IP 주소 간단히 확인
zeta@zeta-MS-7E12:~$ hostname -I
 
# 상세 네트워크 정보 확인 (인터페이스별)
zeta@zeta-MS-7E12:~$ ip addr
📤 hostname -I 출력 예시
192.168.1.100   # ← 이 주소를 사용!

🔑 CHAPTER 4

SSH 키 기반 인증 설정 (비밀번호 없이 접속)

⭐
실제 서버 운영 환경에서는 비밀번호 방식보다 키 기반 인증을 사용하는 것이 훨씬 안전하고 편리합니다. Jetson, Raspberry Pi, 원격 서버 모두 키 인증으로 관리하는 것을 권장해요.
1

내 PC에서 키 페어 생성

접속하는 클라이언트(내 PC)에서 실행!

# ed25519 방식으로 키 생성 (최신 권장 방식)
zeta@zeta-MS-7E12:~$ ssh-keygen -t ed25519 -C "zeta-key"
📤 대화식 출력 (엔터 3번이면 끝!)
Generating public/private ed25519 key pair.
Enter file in which to save the key (~/.ssh/id_ed25519): [엔터]
Enter passphrase (empty for no passphrase): [엔터]
Enter same passphrase again: [엔터]
Your identification has been saved in /home/zeta/.ssh/id_ed25519
Your public key has been saved in /home/zeta/.ssh/id_ed25519.pub
⚠️
id_ed25519 가 개인키, id_ed25519.pub 가 공개키예요. 개인키는 절대 다른 사람에게 주거나 서버에 올리면 안 돼요!
2

서버에 공개키 등록

한 번만 등록하면 이후부터 비밀번호 없이 접속!

# 공개키를 서버에 자동으로 복사 (ssh-copy-id 사용)
zeta@zeta-MS-7E12:~$ ssh-copy-id zeta@192.168.1.100
📤 예상 출력
/usr/bin/ssh-copy-id: INFO: Source of key(s) to be installed
zeta@192.168.1.100's password: (마지막으로 비밀번호 입력)
Number of key(s) added: 1
Now try logging into the machine: 'ssh zeta@192.168.1.100'
🔧
ssh-copy-id가 없는 경우 (Windows 등) 수동으로 등록:
# 공개키 내용 출력 → 복사
$ cat ~/.ssh/id_ed25519.pub
# 서버에서 직접 붙여넣기
서버$ echo "공개키내용" >> ~/.ssh/authorized_keys
3

SSH 서버 설정 파일 — sshd_config

SSH 서버 동작 방식은 /etc/ssh/sshd_config 파일로 제어합니다. 아래 주요 항목들을 알아두세요.

# 설정 파일 편집
zeta@zeta-MS-7E12:~$ sudo nano /etc/ssh/sshd_config
설정 항목기본값권장값설명
Port 22 22 또는 변경 SSH 포트 번호. 22 외 다른 번호로 바꾸면 스캔 공격 감소
PermitRootLogin prohibit-password no root 직접 로그인 차단. 반드시 no로 설정 권장
PasswordAuthentication yes no (키 설정 후) 비밀번호 로그인 허용. 키 인증 설정 후 no로 변경
PubkeyAuthentication yes yes 공개키 인증 허용. 키 인증 사용 시 필수
MaxAuthTries 6 3 인증 실패 허용 횟수. 줄일수록 무차별 대입 공격 방어
ClientAliveInterval 0 300 300초마다 클라이언트 생존 확인. 끊긴 세션 정리
# 설정 변경 후 반드시 재시작!
zeta@zeta-MS-7E12:~$ sudo systemctl restart ssh
 
# 설정 파일 문법 검사 (재시작 전에 확인하면 좋음)
zeta@zeta-MS-7E12:~$ sudo sshd -t
# 오류 없으면 아무 출력 없이 끝남 = 정상

자주 발생하는 오류 해결

❌ ssh: connect to host 192.168.1.100 port 22: Connection refused
→ 원인: SSH 서비스가 실행 중이지 않거나, 방화벽이 막고 있어요.
# 서버에서 SSH 서비스 시작
$ sudo systemctl start ssh
# 방화벽 허용 확인
$ sudo ufw allow ssh
❌ WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!
→ 원인: 서버를 재설치했거나 IP를 다른 서버가 사용 중이에요. known_hosts 파일에서 기존 키를 삭제하면 됩니다.
# 내 PC에서 해당 호스트 키 삭제
$ ssh-keygen -R 192.168.1.100
# 이후 다시 접속하면 됨
❌ Permission denied (publickey)
→ 원인: 키 인증 실패. 공개키가 서버에 제대로 등록되지 않았어요.
# 서버에서 authorized_keys 파일 확인
서버$ cat ~/.ssh/authorized_keys
# 파일/디렉토리 권한 확인 (반드시 맞춰야 함!)
서버$ chmod 700 ~/.ssh
서버$ chmod 600 ~/.ssh/authorized_keys
❌ ssh: Could not resolve hostname
→ 원인: 호스트명이나 IP 주소가 틀렸어요. IP를 다시 확인하세요.
# 서버에서 IP 재확인
서버$ hostname -I
서버$ ip addr show
✅ 전체 요약

SSH 핵심 명령어 모음

📦 설치
$ sudo apt update && sudo apt install openssh-server -y
 
⚙️ 서비스 관리
$ sudo systemctl status ssh   # 상태 확인
$ sudo systemctl enable ssh   # 자동 시작 등록
$ sudo systemctl restart ssh  # 재시작
 
🔥 방화벽
$ sudo ufw allow ssh           # SSH 허용
 
🔌 접속
$ ssh 사용자@서버IP          # 기본 접속
$ ssh -p 2222 사용자@서버IP   # 포트 지정 접속

$ ssh-keygen -t ed25519 -C "my-key"  # 키 생성
$ ssh-copy-id 사용자@서버IP         # 공개키 서버 등록
 
📁 파일 전송 (SCP)
$ scp 파일.txt 사용자@서버IP:~/   # 파일 전송
$ scp -r 폴더/ 사용자@서버IP:~/  # 폴더 전송
