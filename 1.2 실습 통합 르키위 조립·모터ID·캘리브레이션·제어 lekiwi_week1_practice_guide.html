1주차 금 · 블록 ②실습 ①②③ 통합LeKiwi 베이스 전용Pi5 + NUC

르키위 조립에서 첫 주행까지
하나로 따라 하는 실습 가이드

박스 개봉 → 모터 ID → 바퀴 위치 확인 → 캘리브레이션 → 바퀴 점검 → 원격 접속 → 키보드·조이스틱 주행.
각 단계마다 합격 기준이 있으니, 통과하고 나서 다음 단계로 넘어가세요.

0오늘 4.5시간의 흐름

실습 ① 조립 1.5h · 실습 ② 모터 셋업·캘리브레이션 45m · 실습 ③ 제어 45m + 트러블슈팅 여유

📦 부품 점검→🔧 조립·배선→🆔 모터 ID→🧭 바퀴 위치→📐 캘리브레이션→🛞 바퀴 점검→🌐 SSH·네트워크→🎮 키보드·조이스틱
💡 비유 — 르키위는 "식당"입니다 라즈베리파이5는 주방(모터를 실제로 움직임), NUC·노트북은 홀의 손님(키보드·조이스틱으로 주문). 둘 사이를 오가는 웨이터가 ZMQ 통신이고, 주문서는 x.vel · y.vel · theta.vel 세 줄짜리입니다. 주문이 5초간 안 오면 주방이 스스로 불을 끕니다(워치독).

이 그림을 이해하면 오늘 생기는 오류의 절반은 스스로 찾을 수 있습니다.

2실습 ① 부품 점검 · 조립 · 배선 (1.5h)

오늘은 바퀴(베이스)만 조립합니다. 로봇팔은 빼 둡니다 — 팔 모터 6개가 버스에 섞이면 ID 충돌·전류 부족 원인을 찾기 어렵습니다.

📦 부품 체크리스트
🔌 배선 규칙 3가지
  1. 보드는 1장만 — 모든 모터를 한 USB 버스(/dev/ttyACM0)에 연결하면 포트 혼동이 사라집니다.
  2. 12V는 모터, 5V는 Pi — Pi5에 12V를 직접 넣으면 즉시 고장. 강압 모듈 출력이 5V인지 멀티미터로 먼저 확인.
  3. 데이지체인 순서 보드 → ID7 → ID8 → ID9. 케이블이 바퀴에 끼지 않도록 타이로 고정.
🧭 옴니휠 배치 (위에서 본 모습, 로봇 앞 = 위쪽)

각도는 check_wheels.py의 WHEEL_ANGLES 기준입니다. 번호는 권장 배치이며, 실제 위치는 3단계에서 확인합니다.

✅ 합격 기준전원 ON 시 보드 LED 점등 · Pi5 부팅 · 모터 3개가 체인으로 연결 · 케이블이 바퀴에 닿지 않음

3실습 ② 모터 ID 설정

새 모터는 공장에서 모두 같은 ID로 나옵니다. 같은 번호의 학생 셋이 동시에 "네!" 하면 누가 대답했는지 모르죠. 그래서 한 번에 모터 하나만 연결해 번호표를 붙입니다.

1
SSH로 Pi5 접속 후 환경 활성화
NUC 터미널
ssh zeta@192.168.50.111
conda activate lerobot
2
모터보드 포트 찾기 — USB를 뺐다 꽂으라는 안내가 나오면 그대로 따릅니다.
Pi5
lerobot-find-port

결과가 /dev/ttyACM0 이 아니면 이후 명령의 포트를 그 값으로 바꿉니다. 권한 오류 시:

Pi5
sudo usermod -aG dialout $USER   # 이후 로그아웃 → 재접속
3
ID 설정 실행
Pi5
lerobot-setup-motors \
  --robot.type=lekiwi \
  --robot.port=/dev/ttyACM0

베이스 전용 lekiwi.py는 역순으로 묻습니다: base_right_wheel(9) → base_back_wheel(8) → base_left_wheel(7). 화면에 모터 이름이 나오면 그 모터 케이블 하나만 보드에 꽂고 Enter.

⛔ 가장 흔한 사고두 개 이상 꽂은 채 Enter → 두 모터가 같은 ID가 되어 이후 스캔에서 한 개만 보이거나 통신 오류가 납니다. 이때는 모터를 하나씩만 꽂고 다시 실행하세요.
✅ 합격 기준세 번 모두 'base_…' motor id set to 7/8/9 출력

4어느 ID가 어느 바퀴? — identify_wheels.py

ID를 붙였어도, 조립할 때 7번 모터를 오른쪽에 달았을 수 있습니다. 이 상태로 주행하면 "앞으로" 눌렀는데 옆으로 갑니다.

1
바퀴를 받침 위에 띄우고 실행 (host가 켜져 있으면 먼저 Ctrl+C)
Pi5
python3 identify_wheels.py --ids 7 8 9
2
ID마다 1.5초 저속 회전 → 돈 바퀴 위치를 1 좌전 2 후방 3 우전 으로 답합니다.
3
마지막에 출력된 값으로 lekiwi.py 상단을 수정합니다.
lekiwi.py
WHEEL_ID_LEFT  = 7    # 좌전 바퀴 모터 ID
WHEEL_ID_BACK  = 8    # 후방 바퀴 모터 ID
WHEEL_ID_RIGHT = 9    # 우전 바퀴 모터 ID

editable 설치(pip install -e .)라면 ~/lerobot/src/lerobot/robots/lekiwi/lekiwi.py를 고치는 즉시 반영됩니다.

✅ 합격 기준"3개 바퀴 매칭 완료" 출력 + lekiwi.py 값 일치

5캘리브레이션 — 바퀴는 왜 간단한가

로봇팔 관절은 "0도가 어디인지(영점)"와 "어디까지 굽는지(범위)"를 손으로 알려줘야 합니다. 바퀴는 끝없이 도는 모터라 영점이 필요 없습니다.

로봇팔 관절 (SO-101 등)르키위 바퀴
모드위치 모드속도 모드 (Operating_Mode = 1)
영점 homing_offset중간 자세에서 측정0 고정
범위관절을 끝까지 움직여 기록0 ~ 4095 전체
사람 작업자세 잡기 · 끝까지 돌리기'c' 입력 한 번
1
host를 처음 실행하면 캘리브레이션을 묻습니다 (다음 6·7단계 명령 사용).

파일이 없으면 자동 생성, 파일이 있으면 Enter = 기존 파일 사용 / c + Enter = 새로 생성.

2
저장 위치 확인
Pi5
ls ~/.cache/huggingface/lerobot/calibration/robots/lekiwi/
cat ~/.cache/huggingface/lerobot/calibration/robots/lekiwi/my_lekiwi.json

파일 이름 = --robot.id. id를 바꾸면 "파일 없음"으로 다시 캘리브레이션을 묻는 이유가 이것입니다.

✅ 합격 기준json에 세 바퀴 모두 "homing_offset": 0, "range_min": 0, "range_max": 4095

6바퀴 점검 — check_wheels.py

원격 주행 전에 Pi5 안에서 직접 바퀴를 돌려 봅니다. 여기서 문제가 없으면 이후 문제는 "네트워크 쪽"으로 좁혀집니다.

Pi5 (바퀴 띄운 상태)
python3 check_wheels.py            # 진단만: 포트·ID·전압·온도
python3 check_wheels.py --spin     # 바퀴 하나씩 정/역방향
python3 check_wheels.py --move     # 좌·우·전·후 방향 확인
python3 check_wheels.py --turn     # 제자리 좌·우회전
점검정상이상 → 조치
ID 스캔7·8·9 모두 ✅누락 → 체인 케이블 · 12V · 3단계 재실행
전압11~13V10V 미만 → 배터리 충전
온도50°C 미만과열 → 전원 끄고 10분 휴식, 바퀴 걸림 확인
--move 방향화면 문구와 실제 방향 일치좌우 바뀜 → 4단계 ID 매칭 재확인

7원격 접속 · 네트워크 확인

1
같은 망인지 확인
NUC

ping -c 3 192.168.50.111    # Pi5 응답 확인
2

Pi5

옵션뜻

watchdog_timeout_ms=5000명령이 5초 끊기면 바퀴 자동 정지 — 안전장치
--robot.cameras='{}'오늘은 카메라 끄기 (영상 전송 부하·장치 번호 충돌 방지)

Pi5 (다른 SSH 창)

sudo nft list ruleset | head -30   # ufw가 inactive여도 nftables·Docker가 막을 수 있음
⚠️ "No command available" 경고가 계속 찍히는 건 정상client가 아직 연결 안 됐다는 뜻입니다. 워치독 문구 "Stopping the base"도 명령이 없을 때 나오는 정상 로그입니다.

Q1. 워치독 5초는 적절한가?
교육실에선 5초, 원본은 0.5초입니다. 사람이 오가는 공장 AGV라면 몇 초가 맞을까요? 짧으면 무엇이 불편하고, 길면 무엇이 위험할까요?
