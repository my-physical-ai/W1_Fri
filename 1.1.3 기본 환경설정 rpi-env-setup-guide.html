🤔 (base)가 뭔가요?

🏠
이해하기 쉽게!

Conda는 "여러 개의 방이 있는 집"과 같아요. 각 방(환경)에는 서로 다른 도구(라이브러리)가 설치되어 있고, (base)는 현관문을 열자마자 들어서는 "거실"입니다.

💡 실제로는 — Miniforge/Mambaforge가 설치되면 기본 Python 환경인 base가 자동으로 활성화되어 터미널 프롬프트에 (base)가 표시됩니다.

라즈베리파이에 Miniforge나 Mambaforge를 설치하면, 터미널(SSH 포함)을 열 때마다 프롬프트 앞에 (base)가 자동으로 붙습니다. 이것은 Python 가상환경(venv)이 아니라 Conda의 base 환경이 자동 활성화된 것입니다.

❌ 설정 전 (매번 이렇게 보임)
(base) zeta@lekiwi:~$
(base) zeta@lekiwi:~$ python --version
Python 3.11.x (conda)
✅ 설정 후 (깔끔한 프롬프트)
zeta@lekiwi:~$
zeta@lekiwi:~$ python --version
Python 3.11.x (system)

venv vs Conda — 핵심 차이

🐍

Python venv

활성화 방법 source .../activate
비활성화 deactivate
설정 위치 ~/.bashrc 등
프롬프트 (venv)
🐻

Conda / Miniforge

활성화 방법 conda activate
비활성화 conda deactivate
설정 위치 ~/.condarc
프롬프트 (base)
⚠️
핵심 포인트: (base)가 표시될 때 deactivate 명령은 효과가 없습니다. 이것은 venv가 아니라 Conda 환경이기 때문입니다. conda deactivate 또는 설정 변경이 필요합니다.

🔍 진단: 어떤 환경인지 확인하는 방법

🩺
왜 진단이 중요할까?

병원에서 감기인지 독감인지 먼저 진단해야 맞는 약을 쓰듯, 터미널의 문제도 venv인지 Conda인지 먼저 확인해야 올바른 해결책을 쓸 수 있습니다.

1
프롬프트 확인하기
터미널 프롬프트 앞에 무엇이 표시되는지 확인
터미널 
# (base) → Conda 환경
(base) zeta@lekiwi:~$

# (venv) 또는 (myenv) → Python venv
(myenv) zeta@lekiwi:~$

# 아무것도 없음 → 가상환경 비활성 상태
zeta@lekiwi:~$
2
환경 변수로 확인하기
환경 변수를 직접 조회하여 정확한 환경 확인
진단 명령어 
# Conda 환경인 경우
echo $CONDA_DEFAULT_ENV
base

# Python venv인 경우
echo $VIRTUAL_ENV
/home/zeta/myenv

# Conda 정보 전체 확인
conda info
3
설정 파일에서 검색하기
자동 활성화 설정이 어디에 있는지 전체 검색
전체 검색 
grep -rn "activate\|VIRTUAL_ENV\|venv\|conda" \
  ~/.bashrc ~/.profile ~/.bash_profile \
  /etc/profile /etc/profile.d/ 2>/dev/null

🔧 해결 1: Conda (base) 자동 활성화 끄기

🚪
이해하기 쉽게!

집에 들어올 때 자동으로 거실 불이 켜지는 설정을 끄는 것과 같아요. 거실(base)을 쓰고 싶을 때만 직접 불을 켜면 됩니다.

해결 명령어 (한 줄이면 끝!) 
# Conda base 환경 자동 활성화 끄기
conda config --set auto_activate_base false
💡
경고 메시지가 나와도 괜찮습니다!
WARNING: Key auto_activate_base is an alias of auto_activate
이 메시지는 내부적으로 키 이름이 다르게 저장된다는 알림일 뿐, 설정은 정상 적용됩니다.

이 명령이 실제로 하는 일

설정 파일 (~/.condarc)
auto_activate_base: false
⬇️ 터미널 시작 시 참조
~/.bashrc 속 Conda 초기화 코드
conda init 블록
PATH 설정
base 활성화 건너뜀!
⬇️ 결과
터미널 프롬프트
zeta@lekiwi:~$ (깔끔!)

설정 후 SSH 재접속 또는 새 터미널을 열면 (base)가 사라져 있습니다. Conda 환경이 필요할 때는 수동으로 활성화하면 됩니다:

필요할 때만 수동 활성화 
# 필요할 때만 Conda 환경 활성화
conda activate base
(base) zeta@lekiwi:~$

# 또는 특정 환경으로
conda activate myproject
(myproject) zeta@lekiwi:~$

# 비활성화
conda deactivate
zeta@lekiwi:~$

🚀 해결 2: ROS2 Jazzy 자동 로드 설정

🔌
이해하기 쉽게!

매일 출근하면 컴퓨터 전원 → 모니터 전원 → 프로그램 실행을 하듯, .bashrc에 명령을 넣으면 터미널이 열릴 때마다 자동으로 실행됩니다.

💡 실제로는 — ~/.bashrc는 Bash 셸이 시작될 때마다 읽히는 설정 파일입니다. 여기에 source 명령을 추가하면 ROS2 환경 변수가 자동으로 설정됩니다.

ROS2 Jazzy 자동 로드 설정 (한 줄이면 끝!) 
# .bashrc 맨 끝에 ROS2 환경 로드 명령 추가
echo 'source /opt/ros/jazzy/setup.bash' >> ~/.bashrc

# 현재 터미널에 바로 적용
source ~/.bashrc

~/.bashrc가 하는 일

터미널 시작 / SSH 접속
Bash 셸 실행
⬇️ 자동으로 읽음
~/.bashrc 파일 순서대로 실행
기본 설정
alias 정의
conda init 블록
source /opt/ros/jazzy/setup.bash
⬇️ 결과
사용 가능한 환경
ROS2 명령어 사용 가능
ros2 topic, ros2 node 등
⚠️
>>와 >의 차이를 꼭 기억하세요!
>>는 파일 끝에 추가 (append)하고,
>는 파일을 덮어쓰기 (overwrite)합니다.
>>를 사용해야 기존 설정이 유지됩니다!

리눅스에서 터미널을 열 때 읽히는 설정 파일은 여러 개가 있으며, 상황에 따라 다릅니다:

파일 언제 읽히나? 용도
~/.bashrc 터미널 열 때마다 alias, 환경 변수 (터미널용)
~/.profile 로그인 시 1회 PATH 설정 등 기본 환경
~/.xsessionrc GUI 로그인 시 GUI 앱용 환경 변수 (한글 입력 등)
~/.condarc conda 실행 시 Conda 전용 설정 (채널, 자동 활성화 등)
💡
핵심: ~/.bashrc는 터미널 세션에만 영향을 줍니다. 브라우저 같은 GUI 앱의 환경 변수는 ~/.xsessionrc에 설정해야 합니다.

✅ 최종 확인: 설정이 잘 되었는지 검증

SSH 재접속 후 확인 
# 1. (base) 없이 깔끔한 프롬프트 확인
zeta@lekiwi:~$

# 2. ROS2 명령어가 동작하는지 확인
ros2 --help
usage: ros2 [-h] Call `ros2  -h` ...

# 3. ROS2 환경 변수 확인
echo $ROS_DISTRO
jazzy

# 4. 필요할 때 Conda 환경 활성화 확인
conda activate base
(base) zeta@lekiwi:~$
conda deactivate
zeta@lekiwi:~$

📋 이 가이드에서 배운 것

  • (base)는 Python venv가 아니라 Conda의 base 환경이다
  • deactivate는 venv 전용 명령이라 Conda에는 효과가 없다
  • conda config --set auto_activate_base false로 자동 활성화를 끈다
  • echo 'source ...' >> ~/.bashrc로 ROS2를 자동 로드한다
  • 진단이 먼저! — 프롬프트와 환경 변수로 어떤 환경인지 확인한 뒤 해결한다
