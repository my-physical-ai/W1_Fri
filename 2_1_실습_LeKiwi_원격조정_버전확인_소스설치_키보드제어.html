1 르로봇(LeRobot) 버전 확인

NUC과 라즈베리파이 양쪽에서 르로봇 버전을 확인합니다. 버전이 다르면 통신 프로토콜 불일치로 에러가 납니다.

🖥️ NUC에서 확인

NUC 터미널
# 르로봇 가상환경 활성화
conda activate lerobot

# 방법 1: pip로 버전 확인
pip show lerobot
# 출력 예시:
# Name: lerobot
# Version: 0.1.0.dev (또는 특정 버전)
# Location: /home/zeta/lerobot/src

# 방법 2: git 커밋으로 확인 (소스 설치인 경우)
cd ~/lerobot
git log --oneline -1
# 출력 예시: a1b2c3d (HEAD -> main) Add teleop support

# 방법 3: Python에서 직접 확인
python -c "import lerobot; print(lerobot.__version__)"

🍓 라즈베리파이에서 확인

라즈베리파이 (SSH)
# SSH로 접속
ssh zeta01@라즈베리파이IP

# 가상환경 활성화
conda activate lerobot

# 버전 확인 (동일한 방법)
cd ~/lerobot
git log --oneline -1
pip show lerobot
💡 버전 일치 확인 방법 양쪽에서 git log --oneline -1의 커밋 해시(예: a1b2c3d)가 동일해야 합니다.
다르면 → 아래 「2. 르로봇 업그레이드」를 실행하세요.

2 르로봇(LeRobot) 업그레이드

버전이 다르거나 최신 기능이 필요할 때 업그레이드합니다. NUC과 라즈베리파이 양쪽 동일하게!

⬆️ 업그레이드 절차 (양쪽 동일)

1
현재 변경사항 백업 
cd ~/lerobot

# 현재 변경한 파일 확인
git status

# 변경사항이 있으면 백업 (stash)
git stash save "업그레이드 전 백업"
2
최신 소스 가져오기 
# 최신 코드 내려받기
git pull origin main

# 의존성 업데이트
pip install -e ".[feetech]" --break-system-packages
3
업그레이드 확인 
# 버전 확인
git log --oneline -1
pip show lerobot
4
백업한 변경사항 복원 (필요시) 
# 백업한 내용 복원
git stash pop

# 충돌이 있으면 수동 해결 필요
# 이번 실습에서는 커스텀 소스를 덮어쓸 것이므로 복원하지 않아도 됩니다
🚨 업그레이드 후 반드시 커스텀 소스를 다시 덮어씌우세요! git pull하면 우리가 수정한 config_lekiwi.py, lekiwi.py 등이 원본으로 돌아갑니다. 아래 「3. 소스 파일 업데이트」를 반드시 다시 실행하세요.

3 소스 파일 업데이트 (가장 중요!)

다운로드한 teleoperate_base_keyboard.zip의 파일들을 정확한 위치에 복사합니다.

📂 파일 경로 구조

~/lerobot/ ├── src/lerobot/robots/lekiwi/ ← 프레임워크 핵심 파일 │ ├── config_lekiwi.py ← ⭐ 덮어쓰기 (양쪽) │ ├── lekiwi.py ← ⭐ 덮어쓰기 (파이만) │ ├── lekiwi_host.py ← ⭐ 덮어쓰기 (파이만) │ ├── lekiwi_client.py ← ⭐ 덮어쓰기 (NUC만) │ └── __init__.py ← 건드리지 마세요 │ └── examples/lekiwi/ ← 실행 스크립트 ├── teleoperate_base_keyboard.py ← ⭐ 새로 추가 (NUC만) ├── identify_wheels.py ← ⭐ 새로 추가 (파이만) ├── check_wheels.py ← ⭐ 새로 추가 (파이만) └── teleop_joystick_2.py ← 새로 추가 (NUC만, 선택)

🍓 라즈베리파이 — 파일 복사 명령

📌 ZIP 파일을 먼저 라즈베리파이로 전송하세요 NUC에서 scp로 보내거나, USB 메모리로 복사합니다.

# 5. 복사 확인
ls -la ~/lerobot/src/lerobot/robots/lekiwi/config_lekiwi.py
ls -la ~/lerobot/src/lerobot/robots/lekiwi/lekiwi.py

4 NUC: X11 디스플레이 설정 (우분투 필수)

키보드 제어 라이브러리(pynput)는 Wayland에서 동작하지 않습니다. 반드시 X11으로!

1
현재 세션 확인
NUC 터미널
echo $XDG_SESSION_TYPE
# wayland ← 이러면 키보드가 안 됩니다!
# x11    ← 이러면 OK, 5단계로 건너뛰세요
2
X11로 영구 전환 (한 번만 설정)
NUC 터미널
sudo nano /etc/gdm3/custom.conf

# 아래 줄을 찾아서 수정:
#   #WaylandEnable=true  ← 이것을
#   WaylandEnable=false  ← 이렇게 변경 (# 제거 + true를 false로)

# nano 저장: Ctrl+O → Enter → Ctrl+X

sudo reboot
3
재부팅 후 확인
NUC 터미널
echo $XDG_SESSION_TYPE
# x11 ← 이렇게 나오면 성공!
4
pynput 설치
NUC 터미널
conda activate lerobot
pip install pynput

# 설치 확인
pip list | grep pynput
# pynput  1.7.x  ← 출력되면 OK
🚨 이 단계를 건너뛰면 키보드가 절대 안 됩니다! Wayland 환경에서 pynput은 에러 없이 조용히 실패합니다. 팔은 되는데 바퀴만 안 되면 99% 이 문제입니다.

5 라즈베리파이: 바퀴 모터 ID 확인

바퀴 3개의 모터 ID가 lekiwi.py의 설정과 맞는지 확인합니다

1
바퀴 ID 매칭 실행 (로봇 바퀴를 받침 위에 띄운 상태에서)
라즈베리파이 (SSH)

cd ~/lerobot/examples/lekiwi

# 바퀴를 하나씩 돌려서 어떤 ID가 어느 위치인지 확인

2
lekiwi.py 상단의 ID 값을 결과에 맞게 수정
라즈베리파이 (SSH)
nano ~/lerobot/src/lerobot/robots/lekiwi/lekiwi.py

WHEEL_ID_LEFT  = 7    # ← 좌전 바퀴 ID
WHEEL_ID_BACK  = 8    # ← 후방 바퀴 ID
WHEEL_ID_RIGHT = 9    # ← 우전 바퀴 ID
✅ 빠른 진단: check_wheels.py python3 check_wheels.py --spin으로 각 바퀴를 개별 회전시켜 하드웨어 동작을 빠르게 확인할 수 있습니다.

7 🔧 트러블슈팅

문제가 생기면 여기서 찾으세요

❌ "Timeout waiting for LeKiwi Host to connect expired."

원인: 라즈베리파이 호스트가 먼저 실행 중이지 않거나, IP가 다름

해결:

  • 라즈베리파이에서 hostname -I로 IP 확인
  • teleoperate_base_keyboard.py의 remote_ip 수정
  • NUC에서 ping 라즈베리파이IP로 네트워크 확인

❌ 키보드 WASD 눌러도 바퀴 무반응 (에러 없음)

원인: Wayland 환경 또는 pynput 미설치

해결:

  • echo $XDG_SESSION_TYPE → wayland이면 X11로 전환 (4단계)
  • pip list | grep pynput → 출력 없으면 pip install pynput

❌ "Cycle time reached." + 호스트 자동 종료

원인: config_lekiwi.py가 원본(기본값 30초)인 상태

해결: 3단계의 소스 업데이트를 다시 수행하여 수정된 config_lekiwi.py를 덮어쓰세요

❌ "Overload error!" + "Aborted"

원인: 팔 모터에 과도한 부하 (바퀴 전용 모드에서는 거의 발생하지 않음)

해결: 전원을 껐다 켜거나, 모터 에러 리셋 스크립트 실행

❌ "ModuleNotFoundError: No module named 'lerobot.robots.lekiwi'"

원인: 가상환경 미활성화 또는 르로봇 미설치

해결: conda activate lerobot 후 pip install -e ".[feetech]"
