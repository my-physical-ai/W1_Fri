Pi 4 vs Pi 5 — CPU의 결정적 차이

Pi 4와 Pi 5의 차이는 단순히 성능 차이가 아닙니다. CPU 아키텍처가 달라서 특정 소프트웨어(PyTorch 2.4+)가 Pi 4에서는 원천적으로 실행 불가입니다.

LSE 원자 명령어 (Large System Extensions)

🏪
편의점 계산대 비유

과자가 1개 남았을 때 손님 A와 B가 동시에 "확인 → 빼기 → 저장"을 하면 재고가 -1이 됩니다.
LSE 없이(Pi 4): 3단계 명령어를 따로따로 실행 → 중간에 다른 코어가 끼어들 수 있음 → 데이터 충돌!
LSE 있음(Pi 5): "확인+빼기+저장"을 1개 명령어로 잠금 처리 → 절대 끼어들 수 없음 ✅

PyTorch가 Pi 4에서 왜 안 되는가

🎮
PyTorch란?

로봇에게 "보고 배우는 능력"을 주는 도구 상자입니다. 카메라 영상을 분석해서 팔을 어디로 움직일지 결정하는 AI 두뇌 역할을 합니다. LeRobot은 PyTorch 위에서 동작합니다.

Pi 4에서의 오류 발생 흐름

📦
pip install torch
설치 성공 ✅
→
💥
import torch
Illegal instruction!
→
🛑
프로그램 중단
이후 모든 코드 불가
🚨
핵심: PyTorch 2.4+는 설치는 되지만 import 단계에서 즉시 충돌합니다. 설치가 성공했다고 실행이 되는 것이 아닙니다. ldaddal(LSE 명령어)를 Pi 4 CPU가 인식하지 못해 "Illegal instruction" 오류로 종료됩니다.

PyTorch 기능별 Pi 4 vs Pi 5

PyTorch 기능 Pi 4 Pi 5
pip install (설치) 설치는 됨 설치 됨
import torch (불러오기) Illegal instruction 충돌 정상
텐서 연산 (행렬 계산) 불가 (import 자체 실패) 정상
LeRobot AI 학습/추론 불가 ACT 등 정책 실행
모터 제어만 (torch 없이) 가능 (캘리브레이션) 전체 가능

방법 1: PyTorch 2.3.1 다운그레이드 — LSE를 사용하지 않는 마지막 버전입니다. 단, LeRobot 최신 버전이 torch 2.4+ 기능을 요구하면 다른 오류가 발생할 수 있습니다.

# PyTorch 2.3.1로 고정 (LSE 미사용 마지막 버전) pip install torch==2.3.1 torchvision torchaudio

방법 2: 모터 제어 전용으로만 사용 — LeKiwi의 lekiwi_host.py는 torch를 직접 사용하지 않으므로 캘리브레이션, 텔레오퍼레이션은 가능합니다. AI 추론(policy 실행)만 불가합니다.

⚠️
교육 프로그램에서는 트러블슈팅 시간 낭비를 막기 위해 Pi 5로 교체를 강력 권장합니다.

ROS2 Tier 지원 — Tier 1과 Tier 3의 차이

📱
스마트폰 앱 비유

삼성이 자사 갤럭시에서 직접 테스트하고 보증하는 앱(Tier 1)과, 누군가 올려놓은 비공식 앱(Tier 3)의 차이와 같습니다. Tier가 낮을수록 설치 복잡도 높음, 오류 가능성 높음, 지원 불안정입니다.

T1
완전 공식 지원
ROS2 팀이 직접 매일 테스트. 버그 발생 시 즉시 수정. apt로 바로 설치 가능.
Ubuntu 24.04
T2
부분 공식 지원
가끔 테스트. 웬만하면 작동하지만 보증 없음. 일부 기능 누락 가능.
Windows / macOS
T3
커뮤니티 지원
ROS2 팀이 테스트 안 함. 오류 나도 공식 책임 없음. apt 패키지 없음.
Raspberry Pi OS

교육 현장에서의 실질적 차이

상황 Tier 1 (Ubuntu 24.04) Tier 3 (Pi OS)
ROS2 설치 apt install ros-jazzy-... → 바로 됨 패키지 저장소 없어서 수동 빌드 필요
버그 발생 시 ROS2 팀이 수정, 공식 패치 제공 커뮤니티에 의존, 느리거나 미해결
수업 중 오류 "ROS2 문제인가?" 추적 용이 "Pi OS 특유 문제인가, 내 실수인가?" 혼란
교육 적합성 적합 — 바로 시작 가능 비추천 — Docker 추가 학습 필요

ODROID 호환성 분석

ODROID는 Pi 4와 동일한 LSE 문제를 가진 모델이 있습니다. 모델별로 완전히 다른 결과가 나옵니다.

모델 CPU ARMv LSE PyTorch 2.4+ LeRobot
XU4 Cortex-A15+A7 ARMv7 (32비트!) ❌ ❌ 완전 불가
N2/N2+ Cortex-A73+A53 ARMv8.0 ❌ ❌ Pi 4와 동일 문제
C4 Cortex-A55 ARMv8.2 ✅ 가능성 있음 테스트 필요
M2 Cortex-A76 (RK3588) ARMv8.2 ✅ ✅ Pi 5 수준, 미공식
💡
ODROID-N2+는 Pi 4보다 클럭이 빠르지만, 같은 ARMv8.0 아키텍처라서 Pi 4와 동일한 LSE 문제가 발생합니다. 교육 프로그램 일정을 고려하면 검증되지 않은 하드웨어보다 Pi 5가 가장 안전한 선택입니다.

실습 가이드

환경 구성 체크리스트

르키위 + LeRobot 환경을 구성할 때 아래 순서로 진행하면 트러블슈팅 없이 시작할 수 있습니다.

하드웨어 준비

  • ☐Raspberry Pi 5 (4GB 이상 권장, 8GB 최적) — Pi 4는 PyTorch AI 기능 불가
  • ☐Pi 5 공식 27W 어댑터 (5V/5A) — USB 카메라 2개 + 모터 보드 동시 전력 공급 필요
  • ☐64GB 이상 microSD 카드 (Ubuntu 24.04 + ROS2 + LeRobot 합계 약 14GB+)
  • ☐USB 카메라 2대 (워크스페이스용 + 손목 손목용) — CSI 카메라는 설정 복잡

소프트웨어 설치 순서

  • ☐1단계: Ubuntu 24.04 Server 64-bit 설치 (Raspberry Pi Imager 사용)
  • ☐2단계: SSH 활성화 및 네트워크 설정
  • ☐3단계: ROS2 Jazzy 설치 (apt install ros-jazzy-ros-base)
  • ☐4단계: Miniforge(Conda) 설치
  • ☐5단계: lerobot Conda 환경 생성 및 LeRobot 설치
  • ☐6단계: Feetech SDK + ZeroMQ 설치
  • ☐7단계: 모터 설정 및 캘리브레이션

환경 충돌 방지 설정

# ~/.bashrc 권장 설정 # ROS2와 Conda를 동시 자동 활성화하지 않도록 분리! # ROS2는 필요할 때만 수동 source # source /opt/ros/jazzy/setup.bash ← 주석 처리 # 별칭(alias)으로 필요할 때만 활성화 alias ros='source /opt/ros/jazzy/setup.bash' alias lerobot='conda activate lerobot'
💡
핵심 원칙: ROS2는 시스템 Python을, LeRobot은 Conda Python을 사용합니다. 두 환경을 동시에 활성화하면 충돌이 생깁니다. "ROS2 쓸 때는 ros 명령어, LeRobot 쓸 때는 lerobot 명령어"로 명확히 구분합니다.

🎯 핵심 3줄 요약

  1. Pi 4는 CPU에 LSE가 없어서 PyTorch 2.4+와 LeRobot AI 기능이 원천 불가
  2. Pi 5 + Ubuntu 22.04는 OS가 Pi 5를 지원하지 않아 부팅 자체 불가
  3. Pi 5 + Ubuntu 24.04가 ROS2 Jazzy + LeRobot + PyTorch를 모두 공식 지원하는 유일한 조합
